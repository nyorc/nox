# Sketch It

## 目的

- 對話或檔案裡某段內容字太多讀不下去時，重畫成一張小圖，讓使用者看一眼就懂。
- 不修改任何檔案。

## 要畫哪一段

- 只用對話裡已經講過的內容，不另外調查。
- 預設：上一則助理回覆。
- 使用者有指定：畫指定的內容，例如：
  - 某個主題
  - 「整段討論」
  - 一個檔案或檔案裡的一節，這時先讀那個檔案

## 步驟

1. 寫出問題：用一句話說出這段文字替使用者回答了什麼問題。
   - 使用者在指令後面帶的文字本身是問題時，直接用它。
   - 使用者沒有指定範圍、這段文字又回答了好幾個問題時，選開頭那一節回答的問題；有指定時，問題要涵蓋指定的整個範圍。
   - 圖只畫回答這個問題用得到的部分。
2. 依問題在問什麼，選一種圖：
   - 步驟的先後順序：流程圖(flowchart)
   - 誰呼叫誰、誰依賴誰：依賴圖(dependency graph)
   - 某份資料怎麼產生：資料流程圖(data flow diagram)
   - 某個東西會在哪幾個狀態之間切換、什麼條件讓它切換：狀態圖(state diagram)
   - 依幾個是非問題選出結果：決策樹(decision tree)
   - 改了什麼：改之前和改之後用同一種排版，標出改動的部分；有東西換了位置時，畫成左右兩欄，用箭頭連起來
   - 都不符合：選最接近的形狀，用白話說出它是什麼圖
3. 在 code block 裡畫圖，每行最多 120 個半形字元寬，超過的部分會被終端機自動換行。
   - 每個節點寫成一行文字，不加框，用箭頭、縮排與樹狀線表示關係。
   - 標籤用短語，沿用對話裡用過的詞。決定走哪一條路的條件標在箭頭旁；其他條件、數值、例外寫在圖下方的說明，不寫進節點。
   - 直的線只畫在中文字的左邊：中文字佔兩個半形字元寬，畫在中文字右邊的直線上下對不齊。
4. 圖下方最多列三點說明，每點說一件圖表達不出來的事，例如條件、例外或理由。
5. 最後用一行說明這段文字哪些部分沒畫進圖裡，全部都畫了就省略這一行。

## 輸出

用對話使用的語言，在對話中依序印出：步驟 1 寫出的問題、圖、條列說明、步驟 5 那一行。
