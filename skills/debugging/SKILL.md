# Debugging

一步步縮小範圍、找出真正的原因，先寫報告確認方向，再動手修。

原則：

- 只看證據，不憑空猜測
- 一次只改一件事
- 沒驗證過就不算修好

## 流程

### 1. 重現問題

- 找出每次都會出錯的操作步驟
- 把步驟精簡到最少，但仍然會出錯
- 無法穩定重現，就找不到原因，也無法證明已經修好

### 2. 定位問題

- 把範圍縮到最小，確定錯誤出現在哪一層、哪個元件、哪條程式路徑
- 錯誤顯示的地方，不一定就是原因所在

### 3. 分析根本原因

- 從定位到的地方往回追，找出真正的原因，而且這個原因要能解釋所有症狀
- 分清楚哪個是根本原因、哪個只是症狀：問題出現的地方，常常不是該修的地方

### 4. 寫報告

- 動手改程式之前，先把報告印在回覆裡
- 內容包含：
  - 哪裡出錯
  - 怎麼重現
  - 在哪裡發生
  - 根本原因
  - 打算怎麼修
  - 還會影響什麼
- 印完報告就停下來，等 user 確認方向再修
- 這一步是為了確認方向，免得修錯地方，也順便留下紀錄，以後可以回頭查

### 5. 修正問題

- 在該修的那一層修，改動越小越好
- 不要只是把症狀蓋掉，也不要多改不必要的地方
- 修完後確認錯誤不再出現，其他功能也沒被改壞
